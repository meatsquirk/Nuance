# bs-10 Daltonization — behaviour-test completeness

Independent adversarial grade of the bs-10 daltonization acceptance suite (re-graded 2026-10-13, **DALT-5** pass). I did **not** write these tests and changed no test or product file. Three behaviour phases have now landed and **un-pended** their ACs, so this is a re-grade against the previous (DALT-4) grid:

- **AC-1 (DALT-3)** — `daltonize` is the **real** error-redistribution remap (not the identity shell): it takes the painter's full-strength `projectDichromat` view, measures the a*/b* chroma lost to that collapse, rotates it 90° in the a*/b* plane, and adds it back scaled by severity, with lightness preserved. The one chokepoint `displayedSwatchColor` applies it per the painter's stored profile. `AC-1`'s test runs in the default suite and is graded against the **independent** `referenceDaltonize`, never the shipped `daltonize` against itself.
- **AC-5 (DALT-4)** — the one chokepoint (`displayedSwatchColor`, fed `AppScope.cvdProfile`) drives the remap from the **stored** profile's type **and** severity, not a default. DALT-4 changed no `lib/` body; it un-pended AC-5 and added unit tests pinning that the chokepoint forwards the stored type and severity and that severity scales the remap.
- **AC-7 (DALT-5)** — the error-redistribution remap is **distinct from the simulation projection** by construction (it redistributes the confusion-axis chroma rather than collapsing it), so DALT-5 changed no `lib/` body: it un-pended AC-7 and added a **chokepoint-grain** unit test (`test/display/color_simulation_test.dart`) pinning that `displayedSwatchColor` with daltonization on renders a **different** colour from the same colour + profile under simulation — a shipped-vs-shipped distinctness check that a "daltonize by simulating" refactor fails at the render grain.

The remaining **seven** ACs are still **pending** (stage 3), graded on their design — what the code asserts — not on whether they currently skip. Four of them (AC-2/3/4/8) are **green at the shell baseline by design**: turning daltonization on does not yet drive a screen-level behaviour their Then can separate from "off", so each carries a pre-seeded augmentation row owned by a behaviour phase and is graded **"B pending <phase>"**, not A. The other three still-pending ACs (AC-6/9/10) fail at the red baseline on a real Then or precondition — they discriminate today — and are graded against grade-A design.

Surfaces read to verify every Then is tight and aimed at the right surface: `integration_test/daltonization_test.dart` (the AC tests + `_remapOf` / `_expectKnownSwatchRemapped`), `integration_test/daltonization_harness.dart` (the Given/When/Then vocabulary, fixtures, the independent `referenceDaltonize`, `displayColorOf`/`colorNear`/`displaySwatches`), `integration_test/bs10/pending.dart` (the pending gate), the spec `specs/bs-10-daltonization.feature`, the catalogue + augmentations in `MASTER_PLAN_FOR_FEATURE.md` (§"Acceptance integration test plan") and `modules/ITEST.md` (§"Red baseline" / §"Test augmentations"). Product and unit code read to grade the shipped behaviour: `lib/a11y/cvd/daltonize.dart` (`daltonize`/`daltonizeColor` — error-redistribution over `projectDichromat`), `lib/display/color_simulation.dart` (`displayedSwatchColor` chokepoint; `simulateColor`), `lib/widgets/color_chip.dart` (reads `AppScope.cvdProfile` → chokepoint), `lib/display/display_read_endpoint.dart`, `lib/display/settings_screen.dart` (no-profile region still an empty placeholder — CONTROL-2 not landed), and `test/display/color_simulation_test.dart` (the DALT-5 chokepoint distinctness unit test + the AC-5 type/severity forwarding tests).

## Is the AC-7 distinctness grading non-circular?

**Yes — and DALT-5 closes the residual the previous grid flagged.** The question is whether the suite would reject a "daltonize by simulating" implementation without grading the product's `daltonize` against itself:

- **Acceptance (`TestAC07_DistinctFromSimulation`).** The assertion is `colorNear(displayed, displayColorOf(referenceProjectDichromat(sample, deutan, severity))) == false`. The expected value is the **independent** `referenceProjectDichromat` (bs-08's transcription, the basis the harness header names), not the product's own `daltonize` output — so it is not circular. If `daltonize` returned the dichromat projection, `displayed` would land on (an sRGB-close copy of) that projection and the `isFalse` would fail. The rejection relies on bs-08's graded assumption that the independent projection closely models the shipped `projectDichromat`.
- **Unit (DALT-5, `color_simulation_test.dart`).** Compares the two **shipped** chokepoint outputs directly — daltonization-on vs simulation-on for the same colour + profile — and requires `_channelDistance > 2`, plus `dalt != simulateColor(…)`. This is shipped-vs-shipped, so it needs no projection assumption; a refactor routing daltonization through `simulateColor`/`projectDichromat` fails here even where the pure-function `daltonize` test's inputs would pass. This is the tighter contrast the DALT-4 grid noted was "marginally tighter" if done shipped-to-shipped; it is now in place.

Together the acceptance oracle (independent) and the unit oracle (the separate shipped simulation path) reject the simulate-impl from both ends. Neither reuses `daltonize`'s own output as the expected value. **No circularity; no vacuity.** One minor documentation nit (no grade effect): the harness header (lines 22–24) says AC-7's contrast "uses the shipped projection (`projectDichromat`) directly" — true of the new DALT-5 **unit** test, but the **acceptance** test uses `referenceProjectDichromat`; the header could name both grains.

## Is the `referenceDaltonize` / `colorNear` grading fair?

**Fair, and the previously-disclosed coupling is realized and confirmed.** `colorNear` (0.05 summed) is tight enough to reject the plausible wrong implementations — no-remap, wrong-type remap, and simulate-instead-of-distinguish — because the screen sample shifts far under each type (Lab Δ ≈ 16–71; sRGB shift ≈ 0.078 protan / 0.106 deutan / 0.510 tritan), while loose enough only to absorb the sRGB→CIELAB→sRGB round-trip rounding (measured 0 for the screen sample); a fixture guard confirms it separates the original from a real remap. With DALT-3 landed, the shipped `daltonize` shares the reference's error-redistribution design (full-strength `projectDichromat` view → lost a*/b* chroma rotated 90° → added back scaled by severity, lightness preserved), differing only in using the shipped `projectDichromat` where the reference uses the independent `referenceProjectDichromat`. The two agree to the 8-bit swatch for the screen sample, so the un-pended AC-1/AC-5 pass against an independent reference — the coupling G-2 flagged is a confirmed design match, not an open risk.
