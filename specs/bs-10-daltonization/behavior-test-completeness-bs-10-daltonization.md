# bs-10 Daltonization — behaviour-test completeness

Independent adversarial grade of the bs-10 daltonization acceptance suite (re-graded 2026-10-14, **DALT-10** pass). I did **not** write these tests and changed no test or product file. Eight behaviour phases have now landed and **un-pended** their ACs, so this is a re-grade against the previous (DALT-9) grid.

**What changed since the DALT-9 grid.** The build just completed **DALT-10 (AC-4: "A provenance badge stays distinguishable under daltonization")**. Unlike DALT-9 (a test-only phase), DALT-10 ships a **real `lib/` change**: the provenance tier now renders a **shape** (a per-tier glyph) beside its word, with only the *decorative tint* routed through the one display chokepoint — so daltonization remaps the tint while the tier stays readable from its label + icon. Specifically:

- **NEW `lib/widgets/provenance_icon.dart`** — `ProvenanceIcon` renders `Icon(iconFor(tier), color: tint)`. `iconFor` maps each tier to a distinct glyph (shape); `tintFor` is a per-tier *decorative* base colour routed through the one display chokepoint `displayedSwatchColor(tintFor(tier), settings, profile)` (reads `DisplayScope` settings + `AppScope.cvdProfile` with the same fallbacks as `ColorChip`). With daltonization off (or standalone) the tint is the identity of `tintFor`; with it on the tint is remapped for the stored profile, while the glyph + label are untouched.
- **`lib/readout/provenance_region.dart` and `lib/widgets/provenance_badge.dart`** now render a leading `ProvenanceIcon` beside the label/note column (the column wrapped in `Flexible`, the region/badge body now a `Row`). The **important** structural fact for grading neighbours: `ProvenanceIcon` emits an `Icon`, **not** a circular-`BoxDecoration` `Container`, so it contributes **nothing** to `displaySwatches` (which collects only circular `BoxDecoration` swatches). The displayed-swatch population every other AC reads is unchanged.
- **harness (`daltonization_harness.dart`)** added `remapColor(Color, CvdProfile)` (independent reference remap of an arbitrary display colour: `srgbToLab` → `referenceDaltonize` → `displayColorOf`), `provenanceTintFor(tier)` (= `ProvenanceIcon.tintFor`) and `provenanceIcon(tester, region)` (reads the single `Icon`'s glyph + tint within a region). `remapColor` grades a remapped tint against the **independent** `referenceDaltonize`, never the shipped `daltonizeColor`.
- **`daltonization_test.dart`** un-pended **AC-4** (added `AC-4` to the scaffold guard's `unpended` set → `{AC-1, AC-5, AC-7, AC-2, AC-8, AC-9, AC-3, AC-4}`, map length `10 − 8 = 2`) and strengthened `TestAC04_ProvenanceBadgeReadable` with an off→on control: baseline (off) captures the glyph + `'Measured'` label + base tint and asserts the off tint **is** the base tint; on asserts the **same** glyph + `'Measured'` label survive **while** `on.tint == remapColor(baseTint, deutan)` and `!= baseTint`.
- **`bs10/pending.dart`** — AC-4 row removed (the map now holds only AC-6→DALT-11 and AC-10→CONTROL-2).
- **NEW unit test** `test/widgets/provenance_icon_test.dart` — pins `iconFor`/`tintFor` distinctness, the standalone identity tint, and the chokepoint routing (tint remapped for the fallback deutan profile and for an `AppScope` profile).

**One grade band changed: AC-4 B pending DALT-10 → A.** The strengthened `TestAC04` now discriminates. The off baseline pins the glyph + `'Measured'` label + the original base tint; turning daltonization on **keeps the same glyph and label** while the decorative tint moves onto `remapColor(baseTint, deutan)` (the independent reference) and off the original (`colorNear(on.tint, baseTint) == false`). That proves the tier **survives a real colour change** of its decorative tint, readable from label + icon not colour — exactly the spec's Then ("readable from its label and icon, not its colour"). Against an impl that left the tint un-remapped the `remapColor`/`!= baseTint` pair fails; against the ITEST red baseline (a text-only badge, no icon) the glyph read fails outright. **The TestAC04→DALT-10 augmentation row is now closed.**

**No previously-A row regressed.** DALT-10's `lib/` change is confined to the provenance surfaces, and `ProvenanceIcon` renders an `Icon` (no circular `BoxDecoration`), so the `displaySwatches` population the swatch-reading ACs (AC-1/2/3/5/6/8/9 and both smoke tests) depend on is untouched — no extra swatch, no extra `'Displayed colour'`/`'55'` text, no change to `SpaceSelector.valuesKey`. The shared `_expectKnownSwatchRemapped`/`displaySwatches`/`colorNear` helpers are unchanged; the new harness helpers (`remapColor`/`provenanceIcon`/`provenanceTintFor`) are additive and used only by AC-4. The scaffold guard's `unpended` set + length check (`10 − 8 = 2`) stay consistent with the two-entry `pendingACs` map. **New tally: 10 A / 0 B.**

The remaining **two** ACs are still **pending** (stage 3), graded on their design — what the code asserts — not on whether they currently skip. Both (AC-6→DALT-11, AC-10→CONTROL-2) fail at the red baseline on a real Then or precondition — they discriminate today — and are graded against grade-A design.

Surfaces read to verify every Then is tight and aimed at the right surface: `integration_test/daltonization_test.dart` (the AC tests + `_remapOf` / `_expectKnownSwatchRemapped`), `integration_test/daltonization_harness.dart` (the Given/When/Then vocabulary, fixtures, the independent `referenceDaltonize`, `displayColorOf`/`colorNear`/`displaySwatches`, `storedValuesText`, the new `remapColor`/`provenanceIcon`/`provenanceTintFor`, and the three `given…` screen assemblers), `integration_test/bs10/pending.dart` (the pending gate, now two ACs), the spec `specs/bs-10-daltonization.feature`, and the module plans. Product and unit code read to grade the shipped behaviour: `lib/a11y/cvd/daltonize.dart` (`daltonize`/`daltonizeColor` — error-redistribution over `projectDichromat`, pure, lightness-preserving, identity at severity 0), `lib/display/color_simulation.dart` (`displayedSwatchColor` chokepoint; `settings.daltonization ? daltonizeColor : simulateColor`), `lib/widgets/provenance_icon.dart` (the new tier glyph + chokepoint-routed decorative tint), `lib/readout/provenance_region.dart` + `lib/widgets/provenance_badge.dart` (leading `ProvenanceIcon` beside the label/note column), `lib/readout/space_selector.dart` (`valuesKey`, the stored-values reading AC-8 reads), `lib/display/display_read_endpoint.dart`, `lib/display/settings_screen.dart` (no-profile region still an empty placeholder — CONTROL-2 not landed), and `test/widgets/provenance_icon_test.dart` (the new DALT-10 unit test).

**Grading discipline.** The remap (AC-1/AC-2 control/AC-3/AC-5/AC-6/AC-8 control/AC-9, and now AC-4's tint) is graded against `referenceDaltonize` — an **independent** in-harness error-redistribution remap built on bs-08's independent `referenceProjectDichromat`, never the shipped `daltonize` against itself — via `colorNear` (summed-channel tolerance 0.05 ≈ 13/255, ≈ 4 per channel; tightened from the scaffold's 0.094 by DALT-3 so the smallest real remap — protan ≈ 0.078 — still registers as changed). AC-4's remapped tint is graded against `remapColor` (the `Color`→CIELAB→`referenceDaltonize`→`Color` analogue), so the provenance tint is never checked against the shipped `daltonizeColor`. AC-7's "distinct from simulation" contrast at the acceptance grain uses the independent `referenceProjectDichromat`; the DALT-5 unit test adds the shipped-vs-shipped contrast at the chokepoint. `displaySwatches` reads every circular `BoxDecoration` swatch on screen, and because daltonization-on with simulation-off renders exactly one swatch per chip (the remapped colour; the original-alongside pair appears only under a *simulation*), `_expectKnownSwatchRemapped`'s "a swatch matches the reference AND none is still the original" is well-defined — and `ProvenanceIcon`'s `Icon` adds no swatch to that set.

**Pending map:** `pendingACs` now holds exactly the **two** still-pending ACs, each mapped to its owning behaviour phase (AC-6→DALT-11, AC-10→CONTROL-2). AC-1 (DALT-3), AC-5 (DALT-4), AC-7 (DALT-5), AC-2 (DALT-6), AC-8 (DALT-7), AC-9 (DALT-8), AC-3 (DALT-9) and now AC-4 (DALT-10) are removed from the map — they have landed. The scaffold guard that mirrors this (`unpended = {AC-1, AC-5, AC-7, AC-2, AC-8, AC-9, AC-3, AC-4}`, map length `10 − 8 = 2`) confirms the map shrank by exactly those eight. Every augmentation row (TestAC02→DALT-6, TestAC03→DALT-9, TestAC08→DALT-7, and now **TestAC04→DALT-10**) is **closed**; `TestAC09` carried no augmentation (grade-A design at ITEST-2).

## Is AC-4's move to A earned (G5/G3), and is the augmentation discriminating?

**Yes.** The question is whether the strengthened `TestAC04` proves the tier **survives a real colour change** of its decorative tint — readable from its label + icon, not colour — and whether it would fail against both the text-only shell baseline and a tint-not-remapped impl.

- **The off baseline establishes the starting point.** Before the When, the test asserts the region is present, the `'Measured'` tier word (findsOneWidget), the glyph (captured), and `colorNear(off.tint, provenanceTintFor(measured))` — the decorative tint is the **original** base colour while off.
- **The When drives a real tint change.** Turning daltonization on through the real panel toggle routes the decorative tint through the one `displayedSwatchColor` chokepoint → shipped `daltonizeColor` for the stored deutan profile, which actually moves the tint.
- **The Then proves survival across that change (G3/G5).** `on.glyph == glyph` (the shape held) and `'Measured'` findsOneWidget (the word held) are asserted **while** `colorNear(on.tint, remapColor(baseTint, deutan))` (the tint moved onto the independent reference) and the control `colorNear(on.tint, baseTint) == false` (the tint demonstrably changed). The label + icon assertions are therefore made under a proven real tint remap, not an identity no-op — the tint is the reading that CAN change, and here did.
- **The augmentation discriminates.** Against the ITEST red baseline — a text-only badge with no icon — the `provenanceIcon` read fails (no `Icon` in the region), so the test is red at the shell. Against an impl that rendered the icon but left its tint un-remapped, `colorNear(on.tint, remapColor(...))` fails and the control `!= baseTint` fails. The remap target is the **independent** `remapColor`/`referenceDaltonize`, never the shipped `daltonizeColor`, so a mistyped coefficient in either is caught, not mirrored. The spec Then names "label **and icon**, not its colour" — both are now asserted at grain.
