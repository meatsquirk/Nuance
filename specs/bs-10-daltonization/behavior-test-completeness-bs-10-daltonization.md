# bs-10 Daltonization — behaviour-test completeness

Independent adversarial grade of the bs-10 daltonization acceptance suite (re-graded 2026-10-14, **CONTROL-2** pass). I did **not** write these tests and changed no test or product file. All ten behaviour phases have now landed and **un-pended** their ACs, so this is a re-grade against the previous (DALT-11) grid.

**What changed since the DALT-11 grid.** The build just completed **CONTROL-2 (AC-10: "Without a stored profile, daltonization offers no remap")** — the last pending AC. It ships a **real `lib/` change** — the no-profile affordance in the daltonization control, consulting the saved-profile store (not the injected const-default profile) so the control prompts for a self-assessment only when nothing has actually been saved:

- **`lib/store/cvd_profile_store.dart`** — new `Future<bool> hasSavedProfile() async => (await count()) > 0;`. True **only** when a profile document exists, not when the pipeline is merely running on the const default `loadCvdProfile` falls back to (D-4). The const `CvdProfileStore` constructor is preserved.
- **`lib/onboarding/cvd_profile_read_endpoint.dart`** — new `static CvdProfileStore? maybeOf(BuildContext)` (null when no endpoint is above `context`), the fallible sibling of `of`, for surfaces that also render standalone (the daltonization control).
- **`lib/display/settings_screen.dart`** — `noProfileRegionKey` is no longer an empty `SizedBox`: it now mounts `_NoSavedProfileRegion`, a `StatefulWidget` that in `didChangeDependencies` reads `CvdProfileReadEndpoint.maybeOf(context)` and (when a store is present) issues `store.hasSavedProfile()` once, then a `FutureBuilder` renders a `Text` ("No colour-vision profile saved yet — take a self-assessment before colours can be remapped for your vision.") **iff** the resolved value is `false`; while loading, when `true`, or when no store is mounted it renders `SizedBox.shrink()`.
- **`lib/app/build_app.dart`** — `_AppState.build` now mounts a root `CvdProfileReadEndpoint(store: _profileStore, child: tree)` **above** the `MaterialApp` (so the settings panel in the chrome's `builder` can read it) whenever a store is wired (`_profileStore != null`, i.e. `deps.store != null`). It is left **unkeyed**, so the self-assessment suite's `find.byKey(endpointKey)` still resolves to the onboarding host's keyed endpoint. `_profileStore` is the **same** `CvdProfileStore(deps.store)` the DALT-11 AC-6 listener wraps, so the endpoint and the live-recompute path share one backing store.
- **`integration_test/bs10/pending.dart`** — AC-10 row removed; the map is now **empty** (`const Map<String, String> pendingACs = {}`).
- **`integration_test/daltonization_test.dart`** — the scaffold guard's `unpended` set now holds all ten (`{AC-1, AC-5, AC-7, AC-2, AC-8, AC-9, AC-3, AC-4, AC-6, AC-10}`), map length check `10 − 10 = 0`; and the third scaffold guard now asserts `pendingACs` isEmpty and every AC-1..10 runs in both the default and run-pending modes.

**One grade band changed: AC-10 A pending CONTROL-2 → A un-pended.** AC-10 was already grade-A on red-baseline-discriminating design; CONTROL-2 lands the behaviour it asserts, so `TestAC10_NoProfileNeedsAssessment` now **runs on shipped behaviour** and is A for the same reasons — and it genuinely discriminates (see the dedicated section below). The grade band is unchanged (A→A); what moved is pending→un-pended. **No augmentation row.**

**No previously-A row regressed from the root-endpoint mount.** CONTROL-2's `lib/` change adds (1) a pure read method on the store and (2) a conditionally-mounted, **unkeyed** root `CvdProfileReadEndpoint` plus a self-contained `_NoSavedProfileRegion` inside the settings panel. The neighbour-critical facts: the endpoint is an `InheritedWidget` whose `updateShouldNotify` fires only on a store-instance change (`_profileStore` is a stable field, so a profile-reload `setState` does not rebuild the region); it changes **neither** `AppScope` nor `DisplayScope`, so `ColorChip`, the swatch render path (`displaySwatches` byte-for-byte unchanged), the provenance surfaces (AC-4), and the simulation/stored-value paths (AC-7/AC-8) are untouched; the new region renders `SizedBox.shrink()` in every AC that does not open the panel (and adds no circular `BoxDecoration` swatch when it does). The AC-6 live-recompute path is intact: the root endpoint wraps the **same** backing store as the DALT-11 listener, so `whenSaveProfile(protan)` → `notifyListeners` → `_reloadProfile` → `withCvdProfile(protan)` → re-render still fires. Trees with no store (`deps.store == null`: bare unit trees, bs-01..09 harnesses) mount no endpoint and the region shows no prompt. **New tally: 10 A / 0 B, pending map empty.**

The suite is now **complete**: every AC runs on shipped behaviour in the default run, no AC is skipped, and the pending map is empty.

Surfaces read to verify every Then is tight and aimed at the right surface: `integration_test/daltonization_test.dart` (the AC tests + `_remapOf` / `_expectKnownSwatchRemapped`), `integration_test/daltonization_harness.dart` (the Given/When/Then vocabulary, fixtures, the independent `referenceDaltonize`, `displayColorOf`/`colorNear`/`displaySwatches`, `storedValuesText`, `whenSaveProfile`/`whenClearProfile`, `noProfileRegion`, and the three `given…` screen assemblers), `integration_test/bs10/pending.dart` (the pending gate, now empty), the spec `specs/bs-10-daltonization.feature`, and the module plans. Product and unit code read to grade the shipped behaviour: `lib/a11y/cvd/daltonize.dart` (`daltonize`/`daltonizeColor`), `lib/display/color_simulation.dart` (`displayedSwatchColor` chokepoint), `lib/widgets/color_chip.dart` (the one swatch chokepoint reading `DisplayScope` + `AppScope.cvdProfile`), `lib/store/persistent_store.dart` + `lib/store/drift_persistent_store.dart` (the DALT-11 `changes` seam), `lib/store/cvd_profile_store.dart` (the forwarded `changes` + the new `hasSavedProfile`), `lib/onboarding/cvd_profile_read_endpoint.dart` (the new `maybeOf`), `lib/app/build_app.dart` (the DALT-11 `_AppState` store listener + the CONTROL-2 root `CvdProfileReadEndpoint` mount), `lib/widgets/provenance_icon.dart` / `lib/readout/provenance_region.dart` / `lib/widgets/provenance_badge.dart` (DALT-10 provenance surfaces, unchanged), `lib/readout/space_selector.dart` (`valuesKey`, AC-8), and `lib/display/settings_screen.dart` (the new `_NoSavedProfileRegion` filling `noProfileRegionKey`).

**Grading discipline.** The remap (AC-1/AC-2 control/AC-3/AC-5/AC-6/AC-8 control/AC-9, and AC-4's tint) is graded against `referenceDaltonize` — an **independent** in-harness error-redistribution remap built on bs-08's independent `referenceProjectDichromat`, never the shipped `daltonize` against itself — via `colorNear` (summed-channel tolerance 0.05 ≈ 13/255, ≈ 4 per channel; tightened from the scaffold's 0.094 by DALT-3 so the smallest real remap — protan ≈ 0.078 — still registers as changed). AC-4's remapped tint is graded against `remapColor` (the `Color`→CIELAB→`referenceDaltonize`→`Color` analogue). AC-7's "distinct from simulation" contrast at the acceptance grain uses the independent `referenceProjectDichromat`. AC-10's "needs a self-assessment" is graded against the store's real `hasSavedProfile` (count-of-documents), never the injected const-default profile. `displaySwatches` reads every circular `BoxDecoration` swatch on screen; daltonization-on with simulation-off renders exactly one swatch per chip (the remapped colour), so `_expectKnownSwatchRemapped`'s "a swatch matches the reference AND none is still the original" is well-defined, and `ProvenanceIcon`'s `Icon` and `_NoSavedProfileRegion`'s `Text` add no swatch to that set.

**Pending map:** `pendingACs` is now **empty** — every AC-1..10 has landed. AC-1 (DALT-3), AC-5 (DALT-4), AC-7 (DALT-5), AC-2 (DALT-6), AC-8 (DALT-7), AC-9 (DALT-8), AC-3 (DALT-9), AC-4 (DALT-10), AC-6 (DALT-11) and now AC-10 (CONTROL-2) are all removed from the map. The scaffold guard that mirrors this (`unpended` now all ten, map length `10 − 10 = 0`) and the "with every AC delivered the gate runs them all in either mode" guard (`pendingACs` isEmpty; every AC-1..10 skip reason null in both modes) confirm the suite is fully delivered and nothing was silently re-pended. Every augmentation row (TestAC02→DALT-6, TestAC03→DALT-9, TestAC08→DALT-7, TestAC04→DALT-10) is **closed**; `TestAC06`, `TestAC09` and `TestAC10` carried no augmentation (grade-A design at ITEST-2, now all running).
