# bs-10 Daltonization — behaviour-test completeness

Independent adversarial grade of the bs-10 daltonization acceptance suite. I did **not** write these tests and changed no test or product file. These are **pending** acceptance tests (stage 3), graded on their design — what the code asserts — not on whether they currently skip. The four tests that are **green at the shell baseline by design** (AC-2/3/4/8) carry a pre-seeded augmentation row owned by a behaviour phase and are graded **"B pending <phase>"**, not A; the other six are graded against grade-A design.

Surfaces read to verify every Then is tight and aimed at the right surface: `integration_test/daltonization_test.dart` (the AC tests + `_remapOf` / `_expectKnownSwatchRemapped`), `integration_test/daltonization_harness.dart` (the Given/When/Then vocabulary, fixtures, the independent `referenceDaltonize`, `displayColorOf`/`colorNear`/`displaySwatches`), `integration_test/bs10/pending.dart` (the pending gate), the spec `specs/bs-10-daltonization.feature`, the catalogue + augmentations in `MASTER_PLAN_FOR_FEATURE.md` (§"Acceptance integration test plan") and `modules/ITEST.md` (§"Red baseline" / §"Test augmentations").

**Grading discipline.** The remap (AC-1/AC-5/AC-6/AC-9) is graded against `referenceDaltonize` — an **independent** in-harness error-redistribution remap built on bs-08's independent `referenceProjectDichromat`, never the shipped `daltonize` against itself — via `colorNear` (summed-channel tolerance ≈ 24/255, ≈ 8 per channel). The verified red-baseline run (`--dart-define=BS10_RUN_PENDING=true`) passes AC-2/3/4/8 (green-at-baseline/limited) and fails AC-1/5/6/7/9/10 on their tight Then or named precondition against the identity shell remap / empty no-profile placeholder.

**Pending map:** `pendingACs` holds exactly AC-1..AC-10, each mapped to its owning behaviour phase (AC-1→DALT-3, AC-2→DALT-6, AC-3→DALT-9, AC-4→DALT-10, AC-5→DALT-4, AC-6→DALT-11, AC-7→DALT-5, AC-8→DALT-7, AC-9→DALT-8, AC-10→CONTROL-2); all ten still pending (no behaviour phase has run). The four augmentation rows (TestAC02→DALT-6, TestAC03→DALT-9, TestAC04→DALT-10, TestAC08→DALT-7) are present and open in `modules/ITEST.md` §"Test augmentations" — each names the phase that un-pends its AC.

## Is the `referenceDaltonize` / `colorNear` grading fair?

**Fair, with one disclosed coupling.** `colorNear` is tight enough to reject the plausible wrong implementations — no-remap, wrong-type remap, and simulate-instead-of-distinguish — because the screen sample shifts far under each type (Lab Δ ≈ 16–71), while loose enough (≈ 8/channel) only to absorb the sRGB→CIELAB→sRGB round-trip rounding; a fixture guard confirms it separates the original from a real remap. The residual risk is that the shipped `daltonize` must share the reference's error-redistribution design (chroma rotated 90° and added back, scaled by severity) to agree within tolerance — a genuine but modest coupling that DALT-3 and the G-2 test review must confirm, not a flaw in the grader.
